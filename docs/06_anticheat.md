# 反作弊系統（伺服器權威）

> 核心原則：**客戶端永不採信**。所有狀態由伺服器計算，客戶端只送「淨輸入 + 行動」，
> 伺服器逐項驗證輸入速率、行動速率、射速與移動物理。

## 偵測項目（`server/netcode/anticheat.py`）

| 違規 | 偵測方式 | 處置 |
|---|---|---|
| INPUT_FLOOD | 每秒輸入超過上限（128Hz + 容差）→ 封包洪水 / 巨集 | 警告 → 違規 → 踢除 |
| ACTION_FLOOD | 每秒行動超過上限 → 連點濫用 | 警告 → 違規 → 踢除 |
| FIRE_RATE_ABUSE | 射速冷卻內連續嘗試開火（0.5s 內 n 次）→ trigger bot | 警告 → 違規 → 踢除 |
| TELEPORT | 單 tick 位移超過物理上限（0.35m；合法 ~0.05m） | **伺服器回彈到上一個合法位置** + 速度歸零 |
| SPEED_HACK | 水平速度超過 跑速×加速×容差（7.5 m/s） | 伺服器夾回上限 |
| OUT_OF_BOUNDS | 玩家離開地圖邊界 | 回彈到上一個合法位置 |

## 設計重點

1. **修正優先於懲罰**：TELEPORT/SPEED_HACK 由伺服器權威「回彈/夾速」——
   作弊者永遠無法從中獲利，即使沒被踢除。
2. **遞進處置**：每種違規獨立計數；單項超過閾值（預設 5）→ 踢除（釋放槽位）。
3. **誤判防護**：
   - 回合重置（重生傳送）→ `on_round_reset()` 清空位置追蹤，重生不誤判
   - 死亡玩家不追蹤（復活傳送不誤判）
   - 輸入/行動速率以「每秒滑動窗口」計算，容忍正常玩家 + 封包重送
4. **測試是關鍵**：`tests/test_anticheat.py` 驗證每一項偵測 + 修正 + 踢除，
   並確保「正常玩家（跑步/跳躍/反切）零誤判」。

## 與遊戲整合

- `GameServer` 內建 `anticheat`；`step()` 每 tick 執行移動驗證
- `on_input` / `on_action` / `note_fire_attempt` 在收包路徑掛鉤
- 外部可監聽 `server.on_cheat_report(report)`（記分板/日誌/觀戰警示）
- 踢除寫入 `world.event_log`（"KICK: slotN (原因)"）

## 已知限制（誠實聲明）

- **Aimbot 偵測未實作**（瞄準角瞬移）——因「大 flicks」與真作弊難以區分，
  易誤判；正式版可加「人眼/人手物理上限」統計模型。
- **記憶體/程序注入類作弊**（牆透、全圖透視）無法在伺服器端偵測——
  需客戶端完整性檢查（正式版：Godot 匯出簽名 + 反調試）或伺服器端視覺推理。
- 本系統專注「伺服器可驗證的作弊」（加速/傳送/射速/洪水）——這正是
  伺服器權威架構能 100% 擋下的類別。
